LINGKUNGAN PRAKTIK

Menyiapkan MySQL 8.4 dan phpMyAdmin

Otoritatif: MySQL Community Server 8.4 LTS. Gunakan Laragon sebagai jalur utama atau WampServer sebagai alternatif. phpMyAdmin adalah antarmuka; server MySQL tetap pelaksana akhir. Instalasi dilakukan sekali, sedangkan langkah impor dan pengujian diulang pada pertemuan ini.

Instalasi sekali pada Windows

  1. Unduh Laragon dari laragon.org/download dan MySQL Community Server 8.4 LTS dari dev.mysql.com/downloads/mysql. Gunakan paket laboratorium yang telah memadukan keduanya bila tersedia; jangan mengganti mesin dengan MariaDB untuk bukti penilaian.
  2. Pasang Laragon di lokasi tanpa data pribadi. Dari Menu → MySQL → Version, pilih distribusi MySQL 8.4.x yang disediakan laboratorium. Alternatifnya, gunakan WampServer yang benar-benar memuat MySQL 8.4.x, bukan hanya MariaDB.
  3. Klik Start All. Pastikan Apache dan MySQL berstatus berjalan, porta MySQL 3306 tidak dipakai layanan lain, lalu buka http://localhost/phpmyadmin.
  4. Masuk dengan akun laboratorium. Pada instalasi Laragon lokal baru, pengguna biasanya root dengan password kosong; ikuti kredensial resmi laboratorium bila berbeda dan jangan pernah memasukkannya ke screenshot.
  5. Pilih tab SQL dan jalankan SELECT VERSION();. Checkpoint instalasi lulus hanya jika hasilnya MySQL 8.4.x. phpMyAdmin adalah client; nomor versi server pada hasil kueri adalah bukti mesin.

Langkah laboratorium minggu 3

  1. Pilih menu Import, arahkan ke setup_week3.sql, pertahankan format SQL dan set karakter UTF-8, kemudian tekan Import.
  2. Pastikan basis data aktif bernama praktikum_sbd. Skrip menghapus tabel anak lebih dahulu, membangun ulang tiga tabel, mengisi data, dan menjalankan checkpoint sehingga aman diulang.
  3. Periksa jumlah baris 3 mahasiswa, 2 mata kuliah, dan 3 pendaftaran. Jalankan SHOW CREATE TABLE untuk ketiga tabel dan cocokkan InnoDB, utf8mb4, kunci, serta constraint.
  4. Untuk setiap tugas, uji satu input sah dan sedikitnya satu pelanggaran pada server. Simpan SQL buatan sendiri, hasil kueri verifikasi, versi server, dan 1–5 screenshot pada rekap.

Troubleshooting terarah

Porta 3306 dipakai

Hentikan layanan MySQL duplikat yang Anda kenali atau ubah konfigurasi laboratorium bersama teknisi. Jangan mematikan proses acak. Jalankan kembali SELECT VERSION() setelah layanan aktif.

phpMyAdmin tidak terbuka

Pastikan Apache aktif dan alamat memakai localhost. Jika muncul Access denied, gunakan akun resmi; jangan menebak atau menyimpan password di modul.

Error 1046, 1064, 1054, atau 1146

1046 berarti basis data belum dipilih; 1064 menunjukkan sintaks; 1054 berarti kolom tidak dikenal; 1146 berarti tabel belum dibuat. Baca baris error, pilih praktikum_sbd, lalu ulangi skrip lengkap.

FOREIGN KEY gagal

Buat induk sebelum anak, samakan tipe dan UNSIGNED, gunakan InnoDB, lalu periksa target dengan SHOW CREATE TABLE. Saat reset, hapus anak sebelum induk.

CHECK tampak tidak bekerja

Konfirmasi versi server MySQL 8.4.x, cek bahwa nilai benar-benar membuat predikat FALSE, dan ingat bahwa UNKNOWN akibat NULL tidak sama dengan FALSE; gabungkan NOT NULL bila nilai wajib.

TEORI SEBELUM LAB

Tujuh fondasi skema minggu 3

Skema adalah kontrak data. Ia menyatakan objek apa yang boleh ada, bentuk nilainya, identitas tiap baris, hubungan antarobjek, serta kondisi yang harus selalu dipenuhi. Ketujuh bagian berikut saling menyusun satu kontrak yang diuji oleh DBMS.

01

CREATE TABLE

Definisi dan pentingnya. CREATE TABLE adalah pernyataan DDL untuk mendirikan tabel beserta kolom dan aturan awalnya. Tabel sebaiknya mewakili satu entitas atau kejadian yang jelas. Batas yang jelas mengurangi pengulangan, memudahkan relasi, dan membuat aturan bisnis dapat ditegakkan oleh server, bukan hanya diingat aplikasi.

Mekanisme dan sintaks. Bentuk pokoknya ialah nama tabel, daftar definisi kolom di dalam kurung, lalu opsi tabel. Setiap definisi kolom memuat nama, tipe data, dan constraint kolom; constraint bertingkat tabel dapat diberi nama. Dalam paket ini opsi eksplisitnya ENGINE=InnoDB DEFAULT CHARSET=utf8mb4. Nama yang konsisten dan tanpa spasi memudahkan pemeliharaan.

CREATE TABLE ruang_kelas (
  ruang_id INT NOT NULL,
  kode_ruang VARCHAR(12) NOT NULL,
  PRIMARY KEY (ruang_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

Skenario dan penerapan. Pada sistem jadwal, satu baris ruang_kelas mewakili satu ruang. Di phpMyAdmin, buka basis data, pilih tab SQL, jalankan pernyataan, lalu lihat Structure dan hasil SHOW CREATE TABLE. Kesalahan umum meliputi koma terakhir, kurung tidak seimbang, dua kolom bernama sama, atau tidak memilih basis data. Bagian ini menjadi wadah bagi tipe, kunci, dan constraint berikutnya; setelah skema stabil, minggu selanjutnya dapat memakai tabel itu untuk operasi data.

Contoh pembanding. Tabel kejadian seperti peminjaman berbeda dari tabel entitas: ia menyimpan kapan transaksi berlangsung dan siapa yang terlibat. Walau bentuknya berbeda, urutan kerjanya tetap kebutuhan → kolom → tipe → constraint → uji server.

02

MySQL 8.4 data types

Definisi dan pentingnya. Tipe data menetapkan himpunan nilai dan cara penyimpanan suatu kolom. Pilihan yang tepat mencegah nilai tidak masuk akal, menjaga presisi, dan membantu penggunaan ruang. Gunakan tipe berdasarkan domain, bukan sekadar bentuk tampilan: nomor telepon adalah teks, uang adalah angka presisi, dan tanggal adalah nilai temporal.

Kelompok dan mekanisme. Bilangan bulat mencakup TINYINT hingga BIGINT dan dapat memakai UNSIGNED bila tidak pernah negatif. DECIMAL(p,s) sesuai untuk uang; FLOAT atau DOUBLE cocok bagi pengukuran aproksimasi. CHAR cocok untuk panjang tetap, VARCHAR untuk teks pendek bervariasi, dan TEXT untuk uraian panjang. DATE menyimpan tanggal, DATETIME menyimpan tanggal-jam tanpa sifat zona waktu otomatis, TIMESTAMP memiliki rentang dan perilaku berbeda, sedangkan JSON memvalidasi dokumen JSON.

CREATE TABLE tagihan (
  id BIGINT UNSIGNED NOT NULL,
  jatuh_tempo DATE NOT NULL,
  nominal DECIMAL(12,2) NOT NULL,
  catatan VARCHAR(200)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

Skenario dan penerapan. Tagihan membutuhkan nominal tepat dua desimal dan tanggal yang dapat divalidasi. Menyimpan keduanya sebagai VARCHAR membuat pengurutan, validasi, dan perhitungan rapuh. Di phpMyAdmin, halaman Structure memperlihatkan tipe, panjang, signed/unsigned, dan NULL. Kesalahan lazim adalah memakai FLOAT untuk uang, INT untuk telepon, VARCHAR untuk tanggal, atau ukuran terlalu sempit. Pemilihan tipe berhubungan langsung dengan kompatibilitas FOREIGN KEY dan ekspresi CHECK.

Contoh pembanding. Kode PMI1320 tepat disimpan sebagai CHAR atau VARCHAR karena bukan besaran aritmetis, sedangkan sks cocok sebagai TINYINT UNSIGNED. Pemilihan ini membuat niat domain dapat dibaca langsung dari struktur.

03

PRIMARY KEY

Definisi dan pentingnya. PRIMARY KEY adalah satu constraint yang mengidentifikasi setiap baris secara unik dan tidak mengizinkan NULL. Kunci dapat terdiri atas satu kolom atau gabungan beberapa kolom. Identitas stabil memungkinkan baris dirujuk, diperbarui, dan dihubungkan tanpa bergantung pada atribut yang mudah berubah seperti nama orang.

Mekanisme dan sintaks. Bentuk kolom ringkas dapat ditulis setelah tipe, sedangkan bentuk tingkat tabel CONSTRAINT pk_nama PRIMARY KEY (kolom) lebih jelas dan mendukung kunci komposit. AUTO_INCREMENT dapat membantu menghasilkan angka, tetapi sifat tersebut bukan pengganti PRIMARY KEY. Pilih nilai sempit, stabil, dan tidak memiliki makna yang sering berubah.

CREATE TABLE periode (
  tahun YEAR NOT NULL,
  semester TINYINT NOT NULL,
  mulai DATE NOT NULL,
  CONSTRAINT pk_periode PRIMARY KEY (tahun, semester)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

Skenario dan penerapan. Periode akademik unik berdasarkan pasangan tahun dan semester; masing-masing kolom sendirian belum cukup. Setelah membuatnya di phpMyAdmin, periksa ikon kunci dan bagian Indexes. Uji duplikasi pasangan untuk melihat penolakan server. Kesalahan umum ialah memakai nama sebagai kunci, membiarkan identitas berubah, mendefinisikan lebih dari satu PRIMARY KEY, atau menyusun kunci komposit dengan urutan yang tidak sesuai akses. PRIMARY KEY suatu tabel menjadi sasaran alami FOREIGN KEY pada tabel anak.

Contoh pembanding. Pada tabel transaksi besar, transaksi_id BIGINT UNSIGNED AUTO_INCREMENT dapat menghasilkan identitas teknis, tetapi constraint PRIMARY KEY tetap harus dinyatakan. AUTO_INCREMENT mengisi nilai; PRIMARY KEY menjamin identitasnya.

04

FOREIGN KEY dan relasi

Definisi dan pentingnya. FOREIGN KEY menjaga integritas referensial: nilai pada kolom anak harus menunjuk kandidat kunci yang tersedia pada tabel induk, atau boleh NULL bila kolom memang opsional. Aturan ini mencegah baris yatim dan menjadikan hubungan konseptual benar-benar dijaga oleh server.

Mekanisme dan sintaks. Tulis CONSTRAINT fk_nama FOREIGN KEY (kolom_anak) REFERENCES induk(kolom_induk). Pada InnoDB, kolom kedua sisi harus kompatibel dalam tipe dan atribut penting. Tabel induk dan indeks rujukan harus ada lebih dahulu. Tindakan ON DELETE dan ON UPDATE harus dipilih sadar; RESTRICT menolak perubahan yang merusak hubungan, sedangkan CASCADE meneruskan perubahan dan dapat berdampak luas.

CREATE TABLE peserta_kelas (
  peserta_id BIGINT PRIMARY KEY,
  kelas_id INT NOT NULL,
  CONSTRAINT fk_peserta_kelas FOREIGN KEY (kelas_id)
    REFERENCES kelas(kelas_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

Skenario dan penerapan. Peserta hanya boleh ditempatkan pada kelas yang sudah terdaftar. Buat induk dahulu, kemudian anak melalui tab SQL phpMyAdmin; Relation view dan SHOW CREATE TABLE membantu memeriksa nama serta target. Kesalahan umum adalah perbedaan BIGINT dan INT, signed dengan unsigned, salah nama tabel, mesin bukan InnoDB, atau menghapus induk sebelum anak. Relasi bergantung pada kunci dan tipe data, lalu dapat diperketat oleh NOT NULL bila hubungan wajib.

Contoh pembanding. Relasi opsional seperti dosen pembimbing dapat membolehkan pembimbing_id NULL; relasi wajib seperti detail ke transaksi memakai NOT NULL. Keduanya tetap menolak nilai non-NULL yang tidak memiliki induk.

05

UNIQUE

Definisi dan pentingnya. UNIQUE memastikan tidak ada dua baris memiliki nilai atau kombinasi nilai sama pada kandidat kunci tertentu. Berbeda dari PRIMARY KEY, sebuah tabel dapat memiliki beberapa constraint UNIQUE. Aturan ini cocok untuk kode bisnis, email, nomor sertifikat, atau pasangan atribut yang secara bisnis tidak boleh berulang.

Mekanisme dan sintaks. Bentuk tingkat tabel ialah CONSTRAINT uq_nama UNIQUE (kolom). Untuk aturan gabungan, cantumkan beberapa kolom dalam satu daftar. Pada MySQL, UNIQUE tetap dapat menerima beberapa NULL karena NULL menandai nilai yang tidak diketahui; tambahkan NOT NULL bila setiap baris wajib memiliki nilai dan duplikasi harus selalu tertutup.

CREATE TABLE akun (
  akun_id BIGINT PRIMARY KEY,
  email VARCHAR(160) NOT NULL,
  nama_pengguna VARCHAR(40) NOT NULL,
  CONSTRAINT uq_akun_email UNIQUE (email),
  CONSTRAINT uq_akun_nama UNIQUE (nama_pengguna)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

Skenario dan penerapan. Portal kampus membutuhkan identitas internal serta dua kandidat kunci untuk login. Di phpMyAdmin, jalankan DDL lalu periksa indeks UNIQUE pada Structure. Uji nilai duplikat di server dan simpan pesan penolakan sebagai bukti. Kesalahan lazim adalah menganggap UNIQUE sama dengan NOT NULL, membuat aturan terpisah ketika bisnis memerlukan kombinasi, atau memakai nilai yang sering berubah sebagai PRIMARY KEY. UNIQUE melengkapi PRIMARY KEY dan sering menjadi target relasi yang sah bila sesuai desain.

Contoh pembanding. Aturan UNIQUE (mahasiswa_id, mata_kuliah_id, semester) menolak pendaftaran ganda untuk kombinasi yang sama, namun tetap mengizinkan mahasiswa yang sama mengambil mata kuliah berbeda. Tiga UNIQUE terpisah akan mengubah arti bisnis.

06

NOT NULL

Definisi dan pentingnya. NOT NULL menyatakan sebuah kolom harus memiliki nilai pada setiap baris. NULL bukan nol dan bukan teks kosong; ia menandai ketiadaan atau ketidaktahuan nilai. Menentukan atribut wajib sejak skema dibuat mencegah data setengah jadi masuk ke proses bisnis penting.

Mekanisme dan sintaks. Constraint ini ditulis tepat setelah tipe kolom, misalnya judul VARCHAR(160) NOT NULL. DEFAULT dapat menyediakan nilai saat kolom dihilangkan, tetapi default harus bermakna dan bukan cara menyamarkan data yang seharusnya diminta. PRIMARY KEY secara implisit tidak menerima NULL, sedangkan UNIQUE perlu digabung NOT NULL bila kandidat selalu wajib.

CREATE TABLE pengumuman (
  id BIGINT PRIMARY KEY,
  judul VARCHAR(160) NOT NULL,
  tanggal_terbit DATE NOT NULL,
  lampiran VARCHAR(255)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

Skenario dan penerapan. Pengumuman tanpa judul atau tanggal tidak layak terbit, tetapi lampiran memang opsional. Di phpMyAdmin, halaman Structure menandai apakah Null diizinkan. Uji pengisian yang menghilangkan kolom wajib dan bandingkan dengan kolom opsional. Kesalahan umum ialah menyangka string kosong ditolak NOT NULL, memberi default palsu seperti tanda hubung, atau mewajibkan setiap atribut tanpa memahami proses pengumpulan data. NOT NULL bekerja bersama tipe, UNIQUE, dan CHECK untuk membentuk domain yang lebih ketat.

Contoh pembanding. Kolom selesai_pada DATETIME pada proses yang masih berjalan wajar menerima NULL, sedangkan mulai_pada DATETIME NOT NULL wajib tersedia. Keputusan NULL harus mengikuti keadaan bisnis, bukan kebiasaan memberi NOT NULL ke semua kolom.

07

CHECK

Definisi dan pentingnya. CHECK membatasi nilai baris memakai predikat, misalnya rentang skor atau urutan tanggal. Pada MySQL 8.4 constraint ini ditegakkan ketika data ditambah atau diubah. Aturan dekat dengan data tetap berlaku walau ada beberapa aplikasi yang menulis ke tabel.

Mekanisme dan sintaks. Gunakan nama yang menjelaskan aturan: CONSTRAINT chk_skor CHECK (skor BETWEEN 0 AND 100). Predikat mengevaluasi TRUE, FALSE, atau UNKNOWN; baris ditolak saat hasilnya FALSE. Jika NULL tidak boleh lolos sebagai UNKNOWN, tambahkan NOT NULL pada kolom. CHECK sebaiknya deterministik, hanya merujuk kolom baris yang sama, dan menyatakan satu aturan yang mudah dipahami.

CREATE TABLE reservasi (
  id BIGINT PRIMARY KEY,
  mulai DATE NOT NULL,
  selesai DATE NOT NULL,
  peserta TINYINT NOT NULL,
  CONSTRAINT chk_reservasi_tanggal CHECK (selesai >= mulai),
  CONSTRAINT chk_reservasi_peserta CHECK (peserta BETWEEN 1 AND 20)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

Skenario dan penerapan. Reservasi tidak boleh selesai sebelum mulai dan kapasitas dibatasi. Di phpMyAdmin, jalankan DDL, periksa SHOW CREATE TABLE, lalu coba nilai batas, nilai sah, dan nilai pelanggaran. Kesalahan umum ialah lupa NOT NULL, membalik operator, tidak menguji nilai batas, atau berharap CHECK memeriksa tabel lain. CHECK menutup rangkaian minggu ini: tipe menetapkan domain dasar, kunci dan relasi menjaga identitas, sementara constraint kolom dan baris menegakkan aturan bisnis.

Contoh pembanding. Predikat CHECK (tanggal_selesai >= tanggal_mulai) membandingkan dua kolom pada baris yang sama. Uji tanggal sama, urutan benar, urutan terbalik, dan NULL agar perbedaan TRUE, FALSE, serta UNKNOWN terlihat pada server.
